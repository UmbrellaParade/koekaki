# スマホ版の音声入力仕様

## 目的

こえかきは「音声入力のために、普段の文字入力を犠牲にしない」ことを原則にします。
こえかき独自のQWERTY、かな、フリック、顔文字、絵文字キーボードは作りません。
手打ちするときは、GboardやSamsung Keyboardなど、ユーザーが普段使っている
キーボードへ素早く戻します。

## プラットフォーム別の結論

| 方式 | 音声入力 | 他アプリへ直接入力 | 結論 |
|---|---:|---:|---|
| AndroidネイティブIME | ○ | ○ | 実装の本命 |
| iOS Keyboard Extension | × | 文字挿入のみ○ | 同等の音声体験は不可 |
| 現在のPWA | ○ | × | アプリ内入力・コピー用として継続 |

Androidでは `InputMethodService` と `InputConnection.commitText()` を使い、他アプリの
現在のカーソル位置へ文章を挿入できます。
[Android公式: 入力メソッドの作成](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)

iOSのカスタムキーボードは、Appleの公開仕様上マイクへアクセスできず、
キーボード内でこえかきの音声入力を始める体験は作れません。
[Apple公式: Custom Keyboard](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html)

PWAは自分の画面内でOS標準キーボードを使えますが、AndroidのIMEとして登録できず、
他アプリの入力欄へ直接書き込むこともできません。

## Android版の目標体験

1. 任意のアプリの入力欄で「こえかき」を選びます。
2. 小さな音声専用パネルの「話す」で録音を始め、もう一度押して停止します。
3. 録音中は音量・経過時間・停止・取消だけを見せ、乱れる認識途中文は見せません。
4. 整形完了後、その回の文章だけを現在のカーソル位置へ挿入します。
5. `⌨ いつものキーボード` で直前のIMEへ戻り、顔文字・絵文字・予測変換はそちらで使います。
6. 設定で「音声挿入後に自動でいつものキーボードへ戻る」を選べます。

Android 9（API 28）以降は `switchToPreviousInputMethod()` を第一候補にします。
戻れない端末では、OSのキーボード選択画面を表示します。
IME名はメーカーごとに異なるため、Gboard等のIDをハードコードしません。
[Android公式: InputMethodService](https://developer.android.com/reference/android/inputmethodservice/InputMethodService)

## 設定を隠さない

Typelessで「設定画面があるかも分からない」と感じた問題を繰り返さないようにします。

- 音声パネルに文字付きの `設定` を常時表示する
- ランチャーからも通常の設定画面を開けるようにする
- 初回は「マイク許可」「こえかきを有効化」「キーボードとして選択」「テスト」をチェックリストで見せる
- 未完了項目には、説明だけでなく対応するAndroid設定を開くボタンを置く
- 権限不足、空結果、通信失敗を無反応で終わらせない

## 安全上の原則

- パスワード等の機密入力欄では録音ボタンを無効にし、標準キーボードへ戻す
- 周辺の入力文や他のキー入力を収集しない
- 認識文や音声をデバッグログに残さない
- 入力先の接続が失われたら処理を止め、別の入力欄へ遅れて挿入しない
- 録音中にキーボード切替や設定へ移動する場合は、録音を取り消してから移動する

## 実装順

1. AndroidネイティブIMEの技術実証を作り、固定文字の挿入と直前IMEへの復帰を実機で確かめる
2. 録音開始・停止・取消・状態表示を実装し、一つの認識経路で直接挿入まで通す
3. 整形モード、辞書、簡易整形、エラー案内を既存版と揃える
4. `いつものキーボード` と自動復帰、初回チェックリスト、常時見える設定導線を完成させる
5. Pixel / Samsung、Gboard / Samsung Keyboard、Chrome、LINE、Gmail、メモ系アプリで、日本語・改行・絵文字・顔文字・権限拒否を実機検証する

iOSは同等機能の実装対象にせず、現在のPWAで「録音 → 整形 → コピー／共有」を
改善する別トラックにします。Appleがマイク制約を変更した場合にのみ再評価します。
